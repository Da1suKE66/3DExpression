# 扩展表情与头部跟随的工程评估

软件0.3.0，参数/问卷协议IPP31078-AB90-v3，工程评估协议IPP31078-EVAL-v1。图中共12项：系统性能7项、交互行为5项。工程评估不代替具身感问卷，不增加外部参与者人数。

## 功能与对照

17个真实形变系数覆盖张嘴、左右眨眼、微笑、嘴角下压、眉心上抬、左右眉下压/外侧抬起、左右睁大眼睛、噘嘴及左右抿嘴。“伤心”“惊讶”等只是动作组合的名称，不是识别或推断人的真实情绪。化身没有自动表情、自动眨眼或预录动画。

头部使用MediaPipe面部变换矩阵，按中性校准姿态取相对旋转，采用镜像显示和100ms平滑；最大左右35°、上下25°、侧倾20°。追踪丢失或姿态无效时回中性。A、B使用同一头部驱动，只改变面部表情：A中性、B同步。v2为固定头位及五个系数，v3与v2的原始记录、问卷结果分开，不能把新增动作当成旧版已验收。

## 采集步骤

1. 运行本机服务，在Chrome打开`http://127.0.0.1:8765/?mode=demo&ui=030`。本人阅读知情说明并开启摄像头；保持头部回正、合嘴、睁眼，完成至少3秒中性校准。
2. 展开“工程评估：性能与交互行为”，点击开始。先保持中性至少10秒，完成本项；这段用于参数抖动分析，刻意动作期间的变化不算中性抖动。
3. 选择并开始下一项。张嘴、眨眼、微笑、伤心动作、惊讶动作、皱眉抿嘴、噘嘴各做5次；左右转头、抬低头、侧倾各3次；连续切换按“微笑→伤心动作→惊讶动作→噘嘴”做3轮。本人或操作者根据实际画面填写成功次数或留“未核对”，再点击完成本项。未核对不会自动填满分。
4. 可检查离开镜头和返回。完成后结束并保存评估。保持Chrome可见；切页会暂停可见计时并记录事件。录像另行主动点击开始，连续至少22–25秒，避免在录像期间切页；原始录像保存在本机media/raw。
5. 运行`python3 launch.py evaluate`或双击“评估分析.command”。查看`data/processed/evaluation/report.md`、metrics.csv、results.json和validation_issues.csv。每个版本、每份记录分别报告；不把没有数据的格子填成0。

动作完成用时以实际“开始本项→完成本项”按钮事件计算。它包含用户反应、重复动作和操作时间，不能解读为系统响应延迟；另存可见时间以识别切页影响。中断、未核对和缺失的动作如实保留。

## 指标定义与适用范围

| 类别 | 指标 | 计算或采集办法 | 限制 |
| --- | --- | --- | --- |
| 系统性能 | 端到端延迟 | 独立高速相机同时拍本人脸与显示器；人工标注真人动作开始帧、化身响应开始帧，差值除以核对后的实际拍摄帧率 | 内置合成录像不能包括物理相机前和显示器后的延迟；缺少外部录像则待采集 |
| 系统性能 | 面部跟踪帧率 | 实际推理结果次数/评估页面可见秒数；旧记录按结果时间戳跨度描述 | 不是渲染FPS，也不是1000/单次推理耗时；旧记录可见性未知会注明 |
| 系统性能 | 化身渲染帧率 | 实际renderer.render调用数/页面可见秒数；旧记录报告日志中的实际渲染率中位数 | 不是显示器实际呈现率，CPU与显示器帧率不能混写 |
| 系统性能 | 跟踪成功率 | 标注要求本人面部可见阶段中，检测成功的结果样本/结果样本总数 | 可见阶段仍需对照视频；旧记录仅能给检测样本比例，不能称为逐帧检测准确率 |
| 系统性能 | 丢帧率 | getVideoPlaybackQuality总帧和丢帧计数的区间增量；丢帧增量/总帧增量 | 主动40ms推理间隔是采样策略，不算丢帧；API零总数或缺失时不可报零丢帧 |
| 系统性能 | 跟踪恢复时间 | 外部同步录像标注面部重新进入有效视野帧与“追踪正常”出现帧 | 丢失检测到重获检测的整段时长另存诊断，不冒充从已返回开始的恢复时间 |
| 系统性能 | 表情参数抖动 | 至少10秒已完成中性任务内，逐系数原始及应用参数相邻差分RMS | 排除丢失和超过200ms的间隙；数值依赖采样率，需核对本人实际保持中性 |
| 交互行为 | 面部动作响应成功率 | 已人工核对试次的肉眼观察响应成功数/这些试次的要求次数 | 不能用系数阈值周期数代替真实动作次数；不计未核对试次 |
| 交互行为 | 表情响应时间 | 同步录像标注某次表情输入开始与输出开始，按实际拍摄帧率换算 | 与按钮任务用时分开；单次推理耗时不代替表情响应时间 |
| 交互行为 | 连续动作切换稳定性 | 切换任务中的应用系数相邻差分RMS、跟踪丢失、人工异常备注 | 是信号描述量，动作本身也会变化；没有预设通过阈值，不直接判定用户体验稳定 |
| 交互行为 | 用户任务完成时间 | 每项真实开始/完成事件的墙钟差，另列可见时间 | 不能把固定脚本时长当成用户完成用时 |
| 交互行为 | 不同表情驱动一致性 | 已标记动作中，各通道校准输入与平滑应用系数的配对MAE、Pearson相关，逐动作报告 | 80ms平滑有正常相位差，低变异返回空相关；不是情绪识别准确率 |

另记录`inference_ms`、`frame_to_render_submit_ms`与`video_present_to_render_submit_ms`：分别为计算时间、浏览器提供captureTime时到渲染提交的管线时间、视频合成提交到渲染提交的时间。只在回调mediaTime与本次推理帧匹配时关联时钟；没有captureTime时不臆造相机时间。三者都不是物理glass-to-glass端到端延迟。

## 同步视频标注

`materials/video_metric_annotations.csv`为空模板。每行一个事件，必须填写工程记录的session_id、实际原片相对路径、SHA-256、实际拍摄帧率（非慢动作文件的播放帧率）、输入/输出起始帧和标注者。`capture_rate_verified=yes`仅在本人已核对真实拍摄帧率后填写。

- `metric`：end_to_end_latency、expression_response_time、recovery_time之一。
- `recording_scope=external_face_and_display`：独立相机同时覆盖实际本人脸和显示器，才纳入物理时间指标。
- `recording_scope=browser_composite`：只可作为浏览器画面差值诊断，不写成物理端到端测量。
- 结果同时给出按两帧估计的量化误差界`2000/fps`毫秒。变帧率、插帧、剪辑、慢动作时间轴转换或看不清动作边界时应保留原件、标明限制，不填写虚构的精确毫秒数。

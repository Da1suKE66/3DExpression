# IPP31078 本机操作与验收

当前版本0.3.1，协议IPP31078-AB90-v3.1。真实摄像头待人工验收。软件已完成未加速240秒试用，但该试用为synthetic_test，不证明真人动作映射或问卷结果。

## 保存至少20秒真人演示的五步操作

1. 双击“启动原型.command”，在桌面Chrome打开 http://127.0.0.1:8765 。若页面已有旧服务提示，先在旧终端按Ctrl+C再启动。
2. 先选择原版人头、哆啦A梦或皮卡丘；切换角色后重新校准。勾选知情说明，点击“启动摄像头”并授权，进入“实时预览 / 录像”，正对镜头合嘴睁眼，点击“中性校准”。至少保持3秒，系统需收满30个有效样本；完成后用B检查张嘴、左右眨眼和微笑，再用A确认中性固定。
3. 点击“开始真人演示录像”，连续录制22–25秒。让本人面部小窗与大幅化身同时可见，依次做张嘴、眨眼和微笑，期间可点击画面内A/B切换。不要使用参数回放或软件测试输入。
4. 停止录像，点击“保存01_live.mp4”。程序保存到media/raw/01_live.mp4，并写入.metadata.json和证据清单；已有同名文件不会覆盖，会另加时间后缀。当前Chrome支持原生MP4；只支持WebM的浏览器需先运行安装环境.command以启用本地转换。
5. 播放保存文件，确认至少20秒连续真人和化身画面、动作响应及A/B切换，核对来源与时间。人工验收表填写materials/engineering_acceptance.csv。没有实际完成时保留“真实摄像头待人工验收”。

如内置录制不可用，可用macOS Shift+Command+5录制本地页面22–25秒，保留系统录像原件。若为MOV/WebM，运行项目的本地视频工具转换成MP4；不得仅把扩展名改成mp4。转换步骤见README。相机授权或系统录屏授权均由本人操作，不存在助手代替评分或签署的步骤。

## A/B正式体验的五步操作

1. 按experience_protocol.md的分配表使用P01–P06中尚未使用的匿名编号，选择AB或BA，记录用途选择“探索性体验”；项目组自测使用“内部试用”。同一人保持同一编号，重复试用不要当成新人。
2. 在相同设备、座位、光照和窗口大小下，阅读中性说明，取得同意，连接相机并中性校准。开始前固定参数，正式任务期间不切展示模式、不调增益或画质。窗口变化会暂停任务，恢复原尺寸后才能继续。
3. 点击“开始A/B体验”，按提示完成每条件90秒任务。追踪丢失和页面隐藏暂停有效计时，恢复后继续；不适时立即结束。正式体验一次只有一个化身，真人小窗和参数提示在两条件统一隐藏。
4. 每条件真实填写四题1–7分和一句开放反馈；第一条件之后至少休息15秒，再进入下一条件。不告诉体验者哪一条件应更好，不代填、补填或修饰评分。
5. 点击“保存到项目”并下载JSON备份；完整live_camera会话的两行评分自动写入data/raw/participants.csv。双击“运行分析.command”，先看validation_issues.csv再看results.json、点图和results_note.md。发现重复或冲突时保留原件并核对，不改写成期望结果。

## 工程验收记录

在实时预览 / 录像模式保持B，分别重复张嘴、眨眼、微笑，各建议5次；由操作者填写要求次数、肉眼观察次数和实际视觉响应。另连续运行3–5分钟，记录界面实际fps和结果Hz，主动离开镜头再回到镜头前，记录丢失与恢复。以上是待执行协议，不是已发生事实。

“录制参数”保存原始/校准后/应用系数及实际时间，可用于复核动作范围与近似周期；阈值周期计数不是动作准确率。回放一直标记recorded_tracking并保留原始来源，不得作为本人实时演示、正式条件或新参与者记录。

相机视频默认只在浏览器内处理；只有本人主动点击录像与保存才写出画面。仅匿名参数也要按项目记录保管。不要在开放反馈中填姓名、电话或学号。

## 三种化身的验收

在B中分别检查缓慢闭眼、睁眼及单眼眨动：闭眼应遮住眼球和高光，出现闭合线，不能只观察参数或判为“眼睛变小即通过”。再检查伤心动作、微笑、张嘴、左右转头、点头和侧倾。每个角色分别校准；不能用软件手动预设代替真人动作验收。A/B期间角色锁定，正式采集建议对所有参与者统一角色，保留完整模型元数据。
